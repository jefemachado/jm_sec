Arquitetura de Catálogos Seguros no SAP Fiori

Uma análise profunda sobre como desenhar matrizes de acesso resilientes para o frontend Fiori, evitando sobreposição de autorizações e garantindo a governança no S/4HANA sob a ótica do Zero Trust.

Jeferson Machado

Arquiteto SecOps & GRC

O Paradigma do Frontend vs. Backend

Na transição do tradicional SAP GUI (ECC) para o S/4HANA, o SAP Fiori altera fundamentalmente a topologia de acesso. O usuário não consome mais transações diretamente no core da aplicação; em vez disso, ele interage com aplicativos no Frontend Server (FES) que se comunicam via OData com o Backend Server (BES).

Isso significa que, do ponto de vista de Segurança e Governança, administrar perfis na PFCG tornou-se um processo bidimensional. Um erro comum em projetos S/4HANA é tratar a segurança do Fiori apenas como "liberação de tiles" (visibilidade), esquecendo da autorização de consumo de dados por trás dos serviços.

1. Segregação de Catálogos de Negócio (Business Catalogs)

O princípio do menor privilégio (PoLP) dita que o usuário deve ter acesso apenas aos aplicativos estritamente necessários para sua função. Para isso, evite a utilização de catálogos standard da SAP em ambiente produtivo.

  • Standard: Utilizados apenas no ambiente de Sandbox para exploração (Prefixo SAP_TC_ ou SAP_BC_).
  • Customizados: Catálogos criados do zero, contendo apenas as Target Mappings e Tiles validadas pelo negócio (Prefixo Z_BC_ ou Y_BC_).

Dica de Arquiteto: Agrupar dezenas de aplicativos não relacionados em um único catálogo gigantesco para "poupar tempo" destrói a sua matriz SoD (Segregation of Duties) no SAP GRC antes mesmo das regras serem executadas.

2. Rastreamento e Automação com Python

Para garantir que não existem serviços OData expostos sem o devido catálogo atrelado, costumo desenvolver rotinas em Python que cruzam a exportação de tabelas de frontend com a matriz de riscos do GRC.

# Script de SecOps para auditoria de Catálogos Fiori
import pandas as pd

def auditar_catalogos(arquivo_export_fiori, arquivo_matriz_risco):
    df_fiori = pd.read_csv(arquivo_export_fiori)
    
    riscos = df_fiori[
        (df_fiori['Catalog_ID'].str.startswith('SAP_')) & 
        (df_fiori['Role_Name'].str.startswith('Z:'))
    ]
    
    if not riscos.empty:
        print("[!] ALERTA: Violação de governança detectada.")
    else:
        print("[OK] Conformidade mantida.")

Conclusão Estratégica

A segurança no SAP Fiori exige muito mais do que conhecimento técnico na transação SU24 ou no Launchpad Designer. Exige visão arquitetural. Ao desenhar catálogos granulares e testar o consumo OData garantimos que o S/4HANA opere estritamente Secure by Design.
